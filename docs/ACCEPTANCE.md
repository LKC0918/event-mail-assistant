# 验收清单

## 模板已验证的范围

本仓库测试使用合成活动和临时目录，并阻断 socket 连接。离线演示产生三份邮件预览，模拟确认及报名结果。此结论只适用于本机逻辑，不等于真实网站或真实邮箱验收。

运行：`python3 -m unittest discover -s tests -v`。测试数量以命令实际输出为准，不沿用其他项目的历史测试数或旧线上验收。

## 接入自己的平台前

- [ ] 同一完整快照读两次只通知一次，重启仍不重复。
- [ ] 分页中途失败、空列表、重复 ID 不抹掉旧记录。
- [ ] 时间及报名时间有明确时区，改期后旧提醒失效。
- [ ] 真实邮件确实进入自己客户端，而非仅 SMTP 已接受。
- [ ] 从日常客户端点回复，保留主题，正文“报名这个”能绑定正确活动。
- [ ] 主题截短、丢失邮件关联头时，仍可使用已签发的主题标记；两者都缺失时会说明无法识别，不猜活动。
- [ ] 回复正文没有指令、仅改主题的邮件不会触发报名。
- [ ] 已收到、已安排和最终结果三种回执语义分开。
- [ ] 多方式和冲突会询问；未授权、已撤回、已截止不提交。
- [ ] 报名线程独立于慢 IMAP / SMTP，开报前准备不复用旧名额。
- [ ] 提交超时只查结果；重启和重复回复都不再次 POST。
- [ ] 如接入持续候补，验证范围和截止；二选一提交后整组锁定，结果不明也不提交另一场。
- [ ] 模拟网络抖动不会每次都发故障/恢复；真正持续故障有告警。
- [ ] 适配器遵守 timeout/deadline；认证失效需要人工登录，不绕过认证。
- [ ] systemd 重启后状态保留，业务心跳和最近成功读取均正常。

真实测试请使用单独演示活动，先关闭真实提交或使用测试环境；确认结果查询来自权威记录。不要拿热门真实活动当测试夹具。

## 没收到回执时

可给个人流程设置操作阈值，例如：回复后两分钟没看到回执，先查垃圾箱、已发送和邮件内容；确认是“回复对应提醒，正文写指令”。这只是人工排查阈值，不是系统的两分钟送达承诺。

若距开报很近，先查任务状态和原平台结果。需要人工接管时先停自动任务，避免重复提交。邮箱全断时无法靠同一邮箱可靠告警，应另配独立健康监测渠道。
