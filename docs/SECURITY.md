# 隐私与公开边界

这个模板从独立空目录整理，公开内容仅包含通用程序、合成示例、测试和文档，不继承私人仓库历史。

| 信息类别 | 处理方式 |
|---|---|
| 机构、标志、真实活动标题与地点 | 移除平台实现，示例全部重建 |
| 账号、身份资料、联系方式 | 示例使用保留域名与虚构用户标识 |
| 密码、授权码、Cookie、Token、二维码 | 不读取、不打包、不提交；真实密码通过环境注入 |
| 真实地址、服务器标识、个人电脑路径 | 示例化，运行目录仅使用通用部署路径 |
| 邮件、运行数据库、日志、备份和截图 | 排除出公开文件；只用假数据测试及示意图 |
| 历史提交 | 新建公开目录及发布历史，不复制原项目 Git 元数据 |

脚本 `scripts/check_public_tree.py` 检查公开文件类型、运行数据、邮箱、地址、个人路径和常见密钥模式。它是辅助检查，**无法保证识别所有机构名称、个人信息或自定义秘密**。新增适配器、图片、日志或 Issue 前，仍须人工核对。建议私有适配器单独保存。

配置文件可能有自己的邮箱和目标地址，也属于私有信息；`.gitignore` 不是已经泄漏后的清理工具。真有秘密进入公开历史，应立即撤销或轮换秘密，再处理历史，不要只删除最新文件。

运行时 SQLite 含活动、授权、回复摘要和结果记录，必须私密保存。程序不会持久化完整无关邮件，但 IMAP 为识别相关回复仍需访问自己的收件/已发送文件夹；请勿把服务描述为完全不能接触其他邮件。

回信绑定和已发送副本校验用于防串场、防重放；本模板不是端到端邮件签名方案，也不面向不可信多用户环境。邮箱被接管时不能依靠短句指令保障授权。

SMTP 接受不代表收件箱送达；收信通了不代表报名成功；提交异常不代表没有提交。保留状态边界，查权威结果。真实接入、长时间运行、供应商兼容性和平台限流都要另外验证。
