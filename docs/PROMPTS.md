# 给 AI 的初始开发提示词

先准备一个可合法读取的活动页面或官方接口说明、两条合成活动、通知方式和时效需求；不用先交账号密码。

```text
我要基于“活动监测与邮件确认助手”搭一个个人自动化工具。
先阅读仓库 README 和适配器接口，再一次最多问我三个关键问题。
把需求拆成：完整读取、增量去重、定时提醒、邮件确认、到点执行、结果核实、异常恢复。
第一版只用模拟数据和邮件预览，所有测试禁止真实网络及真实报名。

目标数据源：待我说明；先确认可用的合法读取方式。
通知要求：每五分钟检查，报名开始前十五分钟提醒；不要把轮询当作送达保证。
确认方式：回复对应提醒，保留主题，正文第一行“报名这个”。
多个方式或时间冲突时继续问我；未确认、撤回、截止后都不提交。
“已收到回复”“已安排报名”“报名成功”分开发回执。
报名执行与邮件处理隔离，开报前做就绪检查，到点重新核验。
提交超时先查结果，不盲目重复；去重和授权状态重启后保留。
持续候补和互斥活动必须另有明确范围与截止授权。

先给可运行的最小版本、简短步骤和验收清单，再分阶段接真实数据和邮箱。
不要读取我的密码文件或登录状态；需要认证时让我在自己的官方页面操作。
完成后说明：做了什么、哪些通过模拟、哪些经过真实验证、哪些还没验证。
```

每次要求改进，最好提供“具体触发 → 预期 → 实际 → 脱敏证据”。例如：回复后只收到收件回执，任务没有进入已安排；请检查绑定、选项核验和状态转换，不先假定是网络慢。
